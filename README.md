# Ателье №4

Локальный тестовый магазин одежды с каталогом, выбором SKU, корзиной, гостевым
оформлением и виртуальной примерочной. Это продолжение предоставленного React/Vite
проекта. Товары и остатки в базе являются демонстрационными. Деньги не списываются.

## Запуск

Требуется Node.js 24+, npm; Python 3 нужен только для аудита данных.

```powershell
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173/`. При первом запуске автоматически создаётся
`server/data/store.sqlite` и девять исходных товаров с размерами XS–XXL. Данные
сохраняются после перезапуска. Путь можно задать переменной `VFR_DB_PATH`.

```powershell
npm test
npm run build
npm run serve
```

`npm run serve` обслуживает собранный `dist` и API на `http://127.0.0.1:4173/`.
В проекте один сервер API на встроенном `node:sqlite`; в режиме разработки он
монтируется в Vite. Отдельный сервер БД и миграции для текущей локальной схемы
не нужны. Схема создаётся в `server/store.js`.

## Аккаунт администратора

Администратор не имеет пароля по умолчанию. Создайте его локально до входа в
панель через переменные окружения:

```powershell
$env:ADMIN_EMAIL='admin@example.test'
$env:ADMIN_PASSWORD='use-a-unique-password-at-least-12-chars'
npm run admin:create
```

После входа в `Профиль` откроется `Админка`: создание товаров и SKU, цены,
остатки, публикация и статусы заказов. Регистрация через сайт всегда создаёт
обычного покупателя. Тестовые аккаунты создаются только в вашей локальной БД.

## Сценарии

- Каталог и карточка товара → размер → корзина → тестовый заказ → история и отмена.
- Примерочная → изменение мерок → выбор изделия и SKU → та же корзина.
- В аккаунте мерки сохраняются по явному действию; гость использует их только
  в текущем сеансе. Сохраняются версии мерок и образы; профиль с производными
  данными можно удалить.
- Каждая строка корзины идентифицируется SKU. Цена, остаток и итог пересчитываются
  сервером в целых тенге. Заказ защищён ключом идемпотентности, остатки меняются
  в транзакции SQLite. Гостевой доступ к заказу основан на секретном токене чека,
  который браузер хранит локально.

API: `/api/catalog`, `/api/orders`, `/api/try-on`, `/api/me/body`, `/api/me/orders`,
`/api/admin/products`, `/api/admin/variants`, `/api/admin/orders`, `/api/model-status`.

## Данные и модель

Проверены оба переданных ZIP. Отчёты: `docs/project-archive-audit.json` и
`docs/smpl-archive-audit.json`. Архив SMPL содержит три параметрические модели
`.pkl` (женская, мужская и нейтральная) и код. Безопасная проверка `shapedirs`
подтвердила 300 компонентов формы в каждой модели; отчёт сохранён в
`docs/smpl-basis-audit.json`. Скрипт `scripts/prepare_smpl_300.py` переносит
все 300 `shapedirs` в риггированные браузерные модели
`public/models/smpl_female_300.glb` и `smpl_male_300.glb`. Первые 10 морфов
сверяются с исходным GLB перед сборкой; несовпадающий источник отклоняется.

Регрессия `src/data/measurement_to_beta.json` восстанавливает первые 10 главных
коэффициентов из пяти мерок пользователя и возвращает полный вектор длиной 300.
Оставшиеся 290 компонентов сохраняются нейтральными: без дополнительных сканов
или антропометрической разметки их достоверно определить нельзя.
Архив проекта также содержит девять исходных товаров. Исходных обучающих
примеров, групп субъектов,
конфигурации обучения и проверяемых метрик регрессии нет. Поэтому обучение и
сравнение ошибок старой и новой модели **не выполнялись**.

Для аудита другого набора геометрии положите его вне `public/`, например в
`data/300shapes/`, и выполните:

```powershell
npm run audit:data -- --path data/300shapes --output docs/300shapes-audit.json
```

Скрипт `scripts/audit_300shapes.py` инвентаризирует папку или ZIP без запуска
непроверенных pickle-файлов. Текущий `SMPL` плюс
процедурная одежда дают лишь схематичную примерку, не физически точную посадку.

**Лицензия:** переданный `SMPL_python_v.1.1.0.zip` ограничивает использование
некоммерческими целями. GLB в `public/models/` являются производными SMPL.
Не публикуйте этот проект как работающий коммерческий магазин без отдельного
разрешения правообладателя и замены тестовых механизмов.

## Пока не подключено

Реальные платежи, доставка, фотографии товаров, загрузка ассетов, восстановление
пароля, локализация на казахский, точная симуляция ткани и обучение регрессии
на размеченных сканах людей.
Каталог и покупка в текущем виде предназначены для локального тестирования.
